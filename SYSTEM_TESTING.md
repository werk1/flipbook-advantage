This document defines the verification policy for `flipbook-advantage`.

## App-Host Verification

Use the smallest set that matches the change:

```bash
npm run generate:importmap
npm run generate:types
npx tsc --noEmit --incremental false
npm run build
```

Run all four commands when changing Payload collections, globals, schemas, package imports or generated types.

## Docker Development

```bash
npm run dev:docker
npm run dev:docker:logs
npm run dev:docker:down
```

Run Docker checks when Dockerfile, docker-compose files, env variables or Payload initialization changes.

## Module-Specific Checks

Run module-specific checks when the module's routes, Payload collections, env variables or package integration changes.

## Documentation-Only Changes

1. Verify paths and links by inspection.
2. Run `git diff --check` to confirm no whitespace errors.
3. Do not run app builds unless the docs also change build/test behavior.

## Package Defects

App-host verification does not replace package-level checks. When a defect is package-owned, document the app-facing symptom locally and fix the defect in the owning package repository using that package's own `npm run type-check`, `npm run build` and `npm run test`.

## Testing Layers

| Layer | Use | Scope |
|---|---|---|
| Type check + build | Fast app-host verification | This app |
| Docker app checks | Runtime, Payload, database, deployment-like | This app |
| Package-local checks | Package defect verification | Owning package repo |
